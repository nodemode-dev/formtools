### API notes

- Every ffmpeg and ffprobe call is an explicit argument list, never a shell string. Paths must be absolute and an existing readable file. Windows children get `CREATE_NO_WINDOW`. Live child processes are tracked and killed at engine shutdown.
- ffprobe results are cached in memory (64 entries) by path, mtime and size.
- `GET /api/media/info`: adds `cover: bool` to each stream (an attached picture, such as FLAC cover art, is a `video` stream flagged `cover`; it is ignored when judging playability and when picking the frame for a thumbnail). `hdr` is non-null only for PQ (`smpte2084`) or HLG (`arib-std-b67`) transfer. `bit_depth` for video falls back to the depth encoded in `pix_fmt`, else 8.
- Playability follows the contract: native is MP4/MOV family with H.264 and AAC or MP3, WebM (file extension `.webm`) with VP8/VP9/AV1 and Opus/Vorbis, and audio-only MP3, AAC (ADTS), WAV (PCM), FLAC and Ogg. `remux` is true when a plan exists: first H.264 video plus the AAC/MP3 audio streams into fragmented MP4, or first VP8/VP9/AV1 video plus Opus/Vorbis audio into WebM; audio-only files go to MP4 (AAC/MP3) or WebM (Opus/Vorbis). A file whose audio has no acceptable codec (for example AC-3 beside H.264) is not remuxable, because the stream copy would silently drop the sound. `remux` is also true for files that already play natively.
- `GET /api/media/thumb`: one frame at 10 percent of the duration (1 s when unknown), retried at 0 s when the seek yields nothing; cover art for audio; 404 when there is neither. The shipped LGPL ffmpeg has no WebP encoder, so ffmpeg writes a scaled PNG to a pipe and Pillow encodes the WebP (quality 82). Cached in `cache/thumbs/` (the folder the image tool's pruning already covers) under a key with a `media|` prefix. At most 3 decodes run at once.
- `GET /api/media/waveform`: ffmpeg decodes the first audio stream to mono 8 kHz signed 16-bit PCM on a pipe; numpy reduces it in 1 MiB chunks to one absolute peak per 40 samples (200 per second, so memory stays small for long files) and then to N peaks by a max over equal spans. Peaks are raw amplitude (0..1, not normalised to the loudest peak); the frontend may scale. N is clamped to 100..4000. Cached as JSON in `cache/waveforms/`. 400 when the file has no audio.
- `GET /api/media/stream`: async endpoint; ffmpeg runs `-c copy` into fragmented MP4 (`frag_keyframe+empty_moov+default_base_moof`; the contract names the first two, `default_base_moof` is added because browsers prefer it) or WebM on stdout, subtitles, data streams and chapters dropped. The first block is read before the response starts so a failure is a 400 and not an empty 200. The child is killed when the response generator is closed on client disconnect. The response is not seekable (no Range). Extra optional query `start` (seconds) restarts the copy from the keyframe at or before that time, so the player can seek by re-requesting; not in the contract.
- `GET /api/media/subtitles`: `embedded` lists only text-convertible subtitle streams (SubRip, ASS, SSA, WebVTT, mov_text and similar); bitmap subtitles (PGS, DVD, DVB) are left out because they cannot become WebVTT without OCR. `external` lists `.srt .ass .ssa .vtt` files in the same folder whose name starts with `<stem>.` (so `movie.en.srt` counts).
- `GET /api/media/subtitle`: `?index=I` or `?file=NAME`. `file` may be a bare name or an absolute path but must sit in the video's folder and end in one of the four subtitle extensions. `.vtt` is served as is; the others convert through ffmpeg (`-f webvtt`). No character-set detection: a non-UTF-8 `.srt` converts as ffmpeg reads it.
- `POST /api/media/snapshot`: `<stem> <HH-MM-SS.mmm>.png` beside the video (colons are not legal on Windows), a numeric `(2)` suffix instead of overwriting. The name is reserved with an exclusive create, then ffmpeg writes to it. `time` beyond the duration is a 400. Full resolution, no pixel-aspect correction.
- `POST /api/media/copy`: validates and probes synchronously (so a bad request is a 400, not a failed job), reserves the output name, then runs the job `media-copy`. Output names `<stem> (remux).ext`, `(trim)` or `(audio)`, with ` (2)` and so on when taken. Progress is ffmpeg's `-progress pipe:1`; the job's `total` is 1000 and `done` is the per-mille of the span (0 total when the duration is unknown). Cancel kills ffmpeg and removes the partial file; a failed run removes it too and the job error carries the end of ffmpeg's stderr. Result: `{path, size, keyframe_cut}`.
- Default containers when `container` is omitted: remux goes to MKV from MP4/MOV/M4V and to MP4 from everything else; trim keeps the source container when allowed (WAV and other audio-only sources become MKA); extract-audio follows the first audio codec (aac and alac to m4a, mp3, flac, opus, vorbis to ogg, anything else to mka).
- Default stream picks (no `streams`): every video and audio stream; subtitles only when the target holds them without conversion (MKV any, MP4/MOV `mov_text`, WebM `webvtt`); attachments only into MKV; data streams never; cover pictures not into WebM. Audio-only targets take the first audio stream (all of them for m4a and mka). An explicit `streams` list is used as given and ffmpeg's refusal comes back as the job error. MP4 and MOV outputs carry a text track for chapters, which is the muxer's doing.
- Trim is a stream copy: `-ss` before the input plus `-t` for the length, so the cut snaps to the keyframe before `start` (the result says `keyframe_cut: true`); `-avoid_negative_ts make_zero`. MP4, MOV and M4A outputs get `+faststart`.
- Container list note: WAV is not in the contract's container list, so a WAV source cannot be trimmed back into WAV.
- A missing ffmpeg returns 503 with a sentence (still downloading, or how to get it); the contract lists 400, 404 and 415 only.
- `formats()` returns the video and audio extension sets from `core/filetypes.py`.
- MCP tools `media_info`, `media_copy` (returns the job; poll with the batch tool's `job_status`) and `media_snapshot`.
- No dependency added: standard library, Pillow and numpy (already pinned). Nothing is bundled: ffmpeg and ffprobe stay external LGPL programs.

### Verification (2026-11-03, Linux x86_64)

Fetch run with `FORM_FFMPEG_AUTO=1` placed ffmpeg 7.1.5 in `~/.local/share/formcut-binaries/ffmpeg-7.1.5-2`; its configure line has `--disable-gpl --disable-nonfree --disable-version3`, `--enable-libvpx --enable-libopus`, no `--enable-gpl`, no `--enable-nonfree`.
