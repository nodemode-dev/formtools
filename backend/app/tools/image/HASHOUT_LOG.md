# image tool HASHOUT_LOG

Decisions, reasons and anything left out, newest first. Code carries no comments; the context lives here.

## v0.3.0 (2026-11-03): image edits and metadata

- New modules: `meta.py` (XMP sidecars, embedded XMP scan, IPTC) and `edit.py` (crop, resize, rotate, flip, save as). Routes sit in `router.py`: `/api/image/edit` on the image router, `/api/meta/read` and `/api/meta/write` on a second router `meta_router`, both registered by the image tool. MCP tools `image_meta_write` and `image_edit` join `image_info`. `GET /api/fs/dirs` is in `routers/fs.py`.
- No new dependency. XML goes through `xml.etree` only; documents containing a DOCTYPE or ENTITY declaration are treated as unreadable.
- Sidecar naming: writes go to `<file name with extension>.xmp` (`photo.jpg.xmp`). Reads check that name first, then the Adobe style `photo.xmp`; the first that exists wins as a whole file. When only the Adobe-style file exists, a write seeds the new `photo.jpg.xmp` from it, so its other properties survive and the Adobe file is left untouched.
- Write preserves everything already in the sidecar: it parses with ElementTree, changes only `xmp:Rating` and `xmp:Label` on the first `rdf:Description` (as attributes; a child-element form is removed first), and re-wraps in an `xpacket` envelope. ElementTree drops comments and padding and may reorder attributes; the XMP content is equivalent.
- Rating 0 is written as `xmp:Rating="0"` and a cleared label as `xmp:Label=""`, not removed, so a sidecar can override a rating or label embedded in the picture. A write that would change nothing and has no sidecar to update creates no file. `rating: null` in the body is ignored; `label: null` clears.
- Effective values (`meta/read`, `info.xmp`): per field, sidecar first, then the embedded packet found by scanning the first 4 MB for an `xmpmeta` element (no decode). Rating -1 (rejected) reads as 0. Label names read case-insensitively: red, orange, yellow, green, blue, purple, violet (as purple), grey, gray, and the Bridge default texts Select (red), Second (yellow), Approved (green), Review (blue), To Do (purple). Unknown text reads as null. Written names are capitalised (`Red`).
- `info.xmp` always carries `rating` and `label` (null when absent); `title`, `description`, `keywords`, `creator`, `rights` only when present. `info.iptc` is always an object, holding present keys only. IPTC is read only for JPEG and TIFF extensions, through `IptcImagePlugin.getiptcinfo`, decoded as UTF-8 with a Latin-1 fallback.
- `meta/read` never fails for one bad path: a missing or unreadable path returns `{rating: 0, label: null}`. More than 2000 paths is a 400.
- Edit: decodes through `decode.render` (orientation applied, display mode), so crop coordinates are in the oriented picture. Rotate degrees are clockwise. A crop outside the picture is refused, not clamped. Resize accepts one of width or height and keeps the aspect for the other. Output formats: jpeg, png, webp, avif, tiff. With no `out.format` the format comes from the `out.path` extension, else from the source extension, else PNG. Default name `<stem> edited.<ext>`; the extension follows the output format.
- Overwrite rules: an existing destination is refused unless `overwrite` is true; replacing the source also needs `out.path` equal to the source. Refusals are 400 (the contract lists no 409). `out.path` whose extension disagrees with `out.format` is a 400.
- Metadata on save: EXIF is carried with orientation reset to 1 where the encoder accepts it (an encoder that rejects it is retried without). ICC is carried only when the source profile is described as sRGB, because `decode.render` already converts other profiles to sRGB pixels, so the old profile would be wrong. Embedded XMP and IPTC are not carried to the new file. JPEG output flattens alpha onto white. Quality defaults: JPEG 92, WebP 90, AVIF 80; PNG and TIFF are lossless (TIFF Deflate). JPEG above 95 uses 4:4:4.
- Writes go to a hidden temporary file beside the destination, then `os.replace`.
- Left out: RAW sidecar formats beyond XMP, label or rating writes into the picture, undo for overwrite.
