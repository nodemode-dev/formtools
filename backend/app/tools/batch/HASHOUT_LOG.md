# batch HASHOUT_LOG

Decisions, reasons and anything left out, newest first. Code carries no comments; the context lives here.

## 2026-11-03 · v0.3.0 · batch tool, presets, rename

### Layout

- `actions.py` holds the catalogue (19 actions, groups Size, Transform, Colour, Filter, Add, Metadata), the parameter coercion and the pixel functions. `naming.py` is the template tokens and file-name safety. `worker.py` is the top-level process function and the encoders. `pool.py` is the executor holder. `service.py` collects inputs, plans, runs (job) and previews. `rename.py` and `regexguard.py` are the rename planner, applier, undo journal and the regex time limit. `presets.py` is the preset store. `router.py` has every endpoint; `__init__.py` registers the tool `batch` and the seven MCP tools.

### Decisions

- Decoding goes through `decode.render` (orientation applied, colour converted to sRGB in display mode). Because pixels are always oriented, `auto-orient` is an accepted no-op marker and EXIF orientation is reset to 1 on every output that keeps EXIF.
- ICC: `render` already converts profiled pictures to sRGB. The source profile is therefore embedded only when it already described sRGB; otherwise the built-in sRGB profile is embedded (a copy of the original would mislabel the converted pixels). `to-srgb` forces the sRGB profile. `strip-metadata` drops EXIF and, unless `keep_icc`, the profile. `set-dpi` and the source dpi go to JPEG, PNG, TIFF and WebP.
- Metadata by format: EXIF and ICC for JPEG, PNG, WebP, AVIF and TIFF; none for BMP and GIF. If Pillow refuses EXIF or ICC for a format the save is retried without them instead of failing the picture.
- "same" format maps jpg, jpe, jfif, png, apng, gif, webp, avif, bmp, dib, tif and tiff to themselves (the source's extension spelling is kept); RAW becomes JPEG; every other source (PSD, EXR, HDR, ICO and so on) becomes PNG. Animated GIF and WebP sources write their first frame. JPEG and BMP flatten alpha onto white; GIF keeps 1-bit transparency; quality 100 on WebP means lossless.
- Writes: each worker encodes into a hidden temporary file (`.formtools-<id>.tmp`) inside the destination folder, the job thread then resolves the final name (it needs the real width and height for `{width}` and `{height}`) and does an `os.replace`. Nothing is ever written under a final name by a worker, a cancelled or failed item leaves no partial file, and names are decided one at a time so two workers cannot race for a name.
- Overwrite policies: `skip` skips an existing name; `rename` writes `name (2).ext`, `(3)` and so on; `replace` overwrites, except that a name which belongs to another source picture of the same run is skipped, and a folder is never replaced. Two outputs that map to one name never overwrite each other: with `rename` the later one is suffixed, otherwise it is skipped. Writing next to the source with the same name and format is therefore `name (2).ext` unless `replace` is chosen explicitly.
- Never outside the destination: expanded names lose path separators and Windows-illegal characters, `..` in `subfolder` is refused, and the final folder is checked to stay under the destination. `keep_folders` mirrors the folder tree below the input folder you gave (not the folder's own name) inside `folder/subfolder`; it does nothing without a `folder`. A destination inside an input folder is not scanned again.
- `{n}` counts every collected picture in input order (folders expanded in natural order, files before sub-folders), including ones later skipped. `{ext}` is the source extension in lower case; the output extension always comes from the format. `{date}` is EXIF DateTimeOriginal, then DateTime, then mtime. `{exif:Name}` looks up the tag name in IFD0 and the Exif IFD. Unknown tokens are a 400.
- The plan predicts `{width}` and `{height}` from the file header and the action chain (`chain_dims`); the run re-resolves the name from the real result size.
- Process pool: a persistent `ProcessPoolExecutor` (spawn context, size CPU count minus one, at least one) created on the first run and shut down by the tool's `shutdown`. The workers import `app.tools.batch.worker`, which imports the package (the spawned child pays the import of FastAPI once). If the pool breaks or cannot start the runner switches to a `ThreadPoolExecutor` of the same size and resubmits the pending items; `FORMTOOLS_BATCH_THREADS=1` forces threads. In a frozen engine threads are used by default (log line "batch runs use threads inside the frozen engine") because a spawned child re-enters the frozen entry point; `FORMTOOLS_BATCH_PROCESSES=1` opts back in. `formtools_engine.py` already calls `multiprocessing.freeze_support()`, so the shell builder can test that opt-in.
- Cancel: `job.check()` runs between completions; on cancel pending futures are cancelled, running ones are awaited and their temporary files removed, and the job returns its counts (state `cancelled`, `result` kept).
- Preview: the source is decoded with `render(path, max(2048, 2 * max))`, and every pixel-valued parameter (crop box, canvas, border, blur and sharpen radius, text size, margins, resize targets) is multiplied by the shrink factor, so the preview is the true result scaled down. Sources Pillow cannot open for a size probe (RAW, EXR and so on) are rendered in full.
- Presets: `data_dir()/presets/<name>.json` holding the normalised actions and output, written atomically. A save validates both with the same code as a run.
- Rename: rules run in order over every name at once. Counters use the position in the `paths` list. `$1` in a regex replacement is accepted as well as `\1`. Plan conflicts: `invalid` (empty, `.` or `..`, an illegal or control character, trailing dot or space, over 255 bytes), `duplicate` (two items map to one name), `exists` (the name is taken by a file that is not moving away). Apply refuses everything when any item is not `none`. Items whose new name is another item's current name (swaps, rotations, case-only changes) go through temporary names in two phases; if any rename fails everything done so far is put back. Undo entries live in `data_dir()/rename-undo.json` (last 20, ids `u1`, `u2` and so on from a persisted counter) and undo refuses when a current file is gone or an old name is taken again.
- Regex time limit method: names are limited to 1024 characters and patterns to 256. A regex rule is run in a short-lived child Python (`-I -S -c`, standard library `re` only) that receives the pattern, replacement and all names as JSON and returns the new names; the parent waits at most 1.0 second (spawn included) and kills the child on timeout, so a catastrophic pattern costs one second and cannot freeze the engine (a thread cannot be killed and `re` holds the GIL). Where there is no child (frozen engine) the pattern is first parsed with `re._parser` and refused when it has nested open-ended repeats, an alternation inside a repeat or more than three open-ended repeats, then run in process. Verified with `^(a+)+$` and `^(a|aa)+$` on a 60 character name: both stopped after 1.0 s.

### Left out or different from the contract

- `POST /api/batch/plan` also accepts `actions` (so `{width}` and `{height}` can be predicted) and each plan item carries an extra `skip` (reason or null). `POST /api/batch/run` job results are exactly `{written, skipped, failed, outputs}`; `skipped` includes inputs that were not pictures and names skipped by the overwrite policy.
- Action parameters beyond the contract: resize `resample` also offers `box`. The `value` of resize is a float; its meaning depends on `mode`.
- No dependency was added. pyvips is not used, as the contract says.
- Throughput on this 2-CPU machine (one worker): about 24 pictures per second for small JPEG to JPEG, 13 for WebP, 20 for TIFF, from 1000 to 2400 pixel sources resized to 800; the first run after start adds about 3 seconds for worker start-up.
