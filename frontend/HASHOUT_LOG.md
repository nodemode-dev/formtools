## v0.6.0 · 2026-11-03 · Preferences parity with formvis

Ported from formvis 1.98.7 (`SettingsDialog` in `app-dialogs.ts`, `controls.ts`, `dialogs.ts`, `prefs.ts`, `dialogs.css`), checked against FORMVIS_SETTINGS_MAP.md (written for 1.96.4; the code was the truth where they differ). `themes.ts` already matches formvis 1.98.7 apart from the skin key, so it was left alone.

Porting checklist, as applied to formtools (map section 9):
- Step 1, tokens and base CSS: `tokens.css`, `scrollbars.css`, `light-mode.css` were already identical copies. Added the `.cv-btn`, `.cv-icon-btn`, `.cv-num` rules from `shell.css` to `dialogs.css`, since formtools' `shell.css` has none.
- Step 2, `dialogs.css`: the base dialog, field, input, note, toggle, slider and swatch rules plus the whole Preferences block (frame, rail, wire, port, section cards, groups, range styling, cols), kept in formvis's class names (`cv-prefs-*`). Sizes are formvis's: frame `min(840px, 100vw - 280px)` by `min(86vh, 780px)`, rail 232 px (76 px collapsed), 44 px head, 40 px tabs, 30 px controls, 46 percent control column. The `.ft-sec`, `.ft-row`, `.ft-check`, `.ft-note` rules stay for the other pages; inside `.cv-prefs-dlg` they are restyled to match (rows, selects, buttons and the checkboxes become switches), so the mounted Desktop utilities and file manager panels need no change.
- Step 7, the dialog: built once in the constructor and toggled with `hidden`; rail with `is-active` and `aria-selected`; cards with `is-current` and fold; click-to-scroll with a 700 ms spy mute; rAF scroll spy (last card at the end of the scroll); the connector wire and port (path written only when it changed, port moved with a transform); collapse button remembered in `formtools.prefsRailCollapsed`; head drag with the spot in `formtools.dialogSpots`; Done, x, Escape (stops propagation so app keys stay quiet) and scrim pointerdown; focus goes to the active rail tab and returns to the opener. There is no open animation in formvis, so none was added.
- Step 6, `prefs.ts`: `Prefs` gained `uiFontSize`, `animations`, `themeAuto`, `themeLight`, `themeDark`, `favouriteThemes` with validating `clean()`. Mirrored: `applyUiFontSize` (tokens plus the generated sheet for literal pixel sizes), `followSystemTheme`, the `nm:ui-settings-changed` event, the `animations-disabled` body class. `applyUiPrefs` runs when the dialog is built (app.ts is not edited) and on every change through `onPrefs`. The storage key stays `formtools.prefs`, every earlier key and value is unchanged.
- Change path: rows call `change(patch)`, which goes through `updatePrefs` (clean, save, notify listeners); the dialog never writes a pref to storage itself. Controls keep a `data-pref` attribute named for the pref key.
- Step 8, row builders (`ui/settings/rows.ts`): `sliderRow` (range, number box, `--pct` fill, scrubbable label, double-click reset), `selectRow`, `toggleRow` (switch), `colorRow`, `buttonRow`, plus `grp`, `note`, `cols`. Added `segmentedRow` and `valueRow`, which formvis does not have. All rows are built once and `set()` writes only a changed value.
- Reset: formvis's confirm dialog does not exist here, so Reset uses the two-click button the app already uses for trash (armed for four seconds, fixed width). It removes `formtools.*`, `formtools_desk_prefs`, `formtools_user_skin`, `formtools_meta_*` and `nodemode_ui_settings`, then reloads. Desk history stores (picks, measures, texts) are kept.

Sections: General, Appearance (28 themes, favourites by right-click, accent, accent intensity, match system appearance with a light and a dark pair, text size, animations), Browser, Viewer, Desktop utilities and Integration (the two mounted panels, same `mount(slot, node, onOpen)`), then the new Keyboard shortcuts (read-only, from the command catalogue; needs `new SettingsDialog(commands)` in `app.ts`, until then it says so), Privacy and data, Engine (status, version, system, tools from `/api/health` and `/api/capabilities`) and About. Viewer gained the existing `smoothZoom` pref as "Animated zoom".

Left out: formvis's layers, brushes, canvas, tools, type, GPU, scratch, generative, plugins and keys sections; i18n (`t`, `onLanguage`, relabel; formtools is English only); `DialogHistory` and `Dialog.remember` (formvis dialogs that keep values); interface scale (`formvis:ui-zoom`, needs the shell's webview zoom); Updates (the updater plugin is loaded but `tauri.conf.json` has an empty pubkey and no endpoints, and no command reaches it); the data folder path (the engine does not report it; the row shows `dataDir` from `/api/capabilities` when the engine adds it, "Not reported by this engine version" until then).

Measured with Playwright under 4x CPU throttling (script kept outside the repo): layout shift 0 on open, on 10 rail clicks, on scrolling, on changes and on reopen. The one shift is the rail collapse button, 0.026 per toggle, flagged by the browser as input-initiated; the rail is a floating panel that changes width, so it was recorded rather than hidden. `vite build` main chunk 269.6 kB (from 258.9 kB).

## v0.2.0 · 2026-11-02 · shell

- Shared family files copied verbatim from formvis 1.98.7 (Apache-2.0), headers included, because the family keeps them byte-identical: `src/ui/themes.ts` (one change: `USER_SKIN_KEY` is `formtools_user_skin`), `src/ui/icons.ts`, `src/ui/dom.ts`, `src/ui/caption-buttons.ts`, `src/styles/tokens.css`, `fonts.css`, `scrollbars.css`, `light-mode.css`. Update them from formvis, never in place, unless the change is formtools-only.
- `index.html` is formvis's, with the theme-boot script kept and its skin key renamed; the terminal-dock boot script and formvis's stylesheet list are gone.
- formtools' own icons live in `src/ui/ft-icons.ts` and are merged into `ICONS` at import, so `icons.ts` stays identical to the family copy. All are original line drawings, 24 px grid, `currentColor` stroke 1.6.
- Shell class names keep the family's `cv-` prefix for the pieces formvis shares (title bar, menus, caption buttons, status, toast, scrim, dialog), so `caption-buttons.ts` and `light-mode.css` work unchanged. formtools' own pieces use `ft-`.
- `menu.ts` is a lean in-window menu bar (no submenus yet). `native-menu.ts` follows formvis's NativeMenus: on macOS in the desktop app the menus are the system's, built from the same `MenuDef` list, and `has-native-menus` hides the in-window bar.
- Command catalogue (`ui/commands.ts`): every command carries `group`, `description` and `useWhen`, the words MCP and the CLI need, so the window bridge in a later phase can expose them without new metadata.
- No i18n yet: English only. Recorded as stubbed in BUILD_NOTES.
- Pages (Home, Browser, Viewer) are built once at start and switched with `hidden`; nothing is rebuilt on navigation.
- Open in its app calls the OS default app through the shell's `open_with_default`. The FormPortal `open_file` hand-off is Phase 10 work.
- Drag and drop: the desktop app uses Tauri's webview drag-drop event (paths), so the shell no longer turns the drop handler off. In a browser tab dropped files have no paths, and a toast says so.

## v0.4.0 · 2026-11-03 · Phases 5, 6 and 7

- The 3D viewer (`ui/model/`) and the document viewers (`ui/docview/`) are separate modules with their own logs. The viewer imports both with a dynamic `import()` the first time a model or document opens, so neither three.js nor highlight.js, markdown-it or pdf.js is in the main chunk (258.9 kB, from 256.7 kB in v0.3.0). Both mount into `.ft-ext` inside the stage, above the image panes, and the viewer bar keeps back, previous, next, information, open in and show in folder for them.
- Routing (`kindOf` in `viewer.ts`): type `model` goes to the 3D viewer; types `text`, `pdf`, `font`, `archive`, `other` and the data extensions (Markdown, CSV, JSON, SQLite) go to the document viewer, which shows any other file as hex. Folders stay out.
- Keys: the module's `key(e)` runs first and before the modifier check, because the document viewer owns Mod+F. Keys typed into a field never reach the viewer's own map. For models and documents the viewer keeps only navigation, Escape, I, F11, Space, ratings and labels.
- Focus: hiding a focused control (switching document panels) drops focus to the body, which silently stopped the viewer's keys. A `focusout` with no next target now returns focus to the stage, and `showExt` focuses the stage when nothing inside the viewer has focus.
- The document viewer's classes use a `dv-` prefix rather than `ft-`; it is self-contained in `docview.css`, so the prefix was kept rather than renamed by hand across a dozen files.
- Document switching: the previous panel stays on screen, dimmed by `.dv-stage.is-loading` behind `delayedIndicator`, until the next panel is ready, and stale panels close after the new one shows. Opening a second file of the kind already on screen re-opens it (it used to keep the first file). Kinds may expose `shown()`, run in the same task that unhides them; the PDF panel fits its pages there, because a hidden panel measures zero width, and it starts at page 1.
- Utilities (`ui/utilities/`): one page with six views built once and switched with `hidden`. Results are patched by key; Duplicates renders the 400 groups that waste the most and says so. Disk usage lays cells out with a squarified treemap (`treemap.ts`) and moves them with CSS variables and `transform`, so a resize relayouts without rebuilding. Run buttons stack "Stop" in the same grid cell as their label, and the trash buttons have a minimum width, so a label change moves nothing. Closeness is disabled, not hidden, for identical-content scans.
- Trash always takes two clicks: the first turns the button into "Move N to the trash?" for four seconds.
- Toasts: a new message takes a fresh node in a fixed-width band. Reusing the visible node let a longer message move it (0.003 under throttling).
- The browser hides `name.ext.xmp` when `name.ext` is in the same folder.
- pdf.js reads its cmaps, standard fonts and wasm decoders from `/pdfjs/`; `vite.config.ts` maps that path to `node_modules/pdfjs-dist` in development and copies the three folders into `dist/pdfjs/` on build, so nothing is vendored into the repository.

## v0.3.0 · 2026-11-02 · Phase 2 finish, Phases 3 and 4

- Browser: multi-select (Mod-click toggles, Shift-click and Shift-arrows extend from the anchor, Mod+A all). `selection()` is the picked set, or the focused item. A reload with `keepSelection` restores the focus ring without touching the picked set, because the batch tools reload the folder after a run.
- Ratings and labels follow Lightroom's keys: 0 to 5 rate, 6 to 9 toggle red, yellow, green and blue, in the browser and the viewer. Tags live in XMP sidecars (`name.ext.xmp`) through `/api/meta/*`; the browser reads them in one batch after each render and paints a badge. The badge stars are the `ftStarFill` icon, not the U+2605 character, because the no-emoji gate scans that range.
- Folder tree (`ui/tree.ts`): roots are the engine's places plus "Computer" (`/`) on macOS and Linux, children load on first expand, and reveal expands the deepest unopened ancestor until the open folder is visible. A reveal after a navigation shifts the rows below (measured 0.0003 under throttling); it is the result the navigation asked for, recorded rather than hidden.
- Viewer: "actual pixels" moved from 1 to A, because digits now rate. Crop (R) is an overlay in image coordinates, with aspect presets; dragging inside the box moves it, outside draws a new one. Resize (Shift+R) and Save as open `SaveDialog`, which never replaces the original unless "Replace the original" is chosen, and gives focus back to whatever had it. Pixel inspector (P) samples a decoded copy (at most 40 megapixels; larger pictures are sampled from a scaled copy) and copies the hex on click.
- Media: every video and audio file opens in the viewer; native containers start at once from the raw file; `/api/media/info` decides whether a lossless remux stream (`/api/media/stream`) replaces it. The remux stream cannot seek by byte range; the bar says so. `MediaBar` adds speed, A-B loop (B), frame steps (comma and period, from the stream's fps), J and L, subtitles as `<track>` elements (embedded and beside the file), snapshots and lossless clips and audio extraction through jobs. Audio gets a waveform canvas, drawn once; the playhead and A-B marks move with CSS variables only.
- Viewer grid rows are pinned (`grid-row` 1, 2, 3) because the media bar leaves the grid when hidden, which had collapsed the stage to zero height.
- Tools page (`ui/tools/`): Batch convert, Resize and Rename built once and switched with `hidden`. Action cards are generated from `/api/batch/actions`; the preview reloads 400 ms after the last change and swaps the image only once the new one has decoded. Rename keeps the applied mapping for Undo, because the plan is recomputed after an apply.
- Jobs (`ui/jobs.ts`): a status-bar button and a popover, polled every 400 ms only while a job runs; rows patch in place.
- Toasts use one slot that updates in place: a stack of three moved the first toast when a second appeared (layout shift 0.0009).

## v0.2.0 · 2026-11-02 · viewer and browser (Phase 2)

- Browser: `patchList` keyed by path; thumbnails load through an IntersectionObserver with a 400 px margin and are decoded off-screen before the `img` is shown, so a tile goes from glyph to picture in one write. Tiles reserve a 4:3 box; `content-visibility: auto` keeps large folders cheap.
- Folder loads keep the old listing on screen until the new one arrives; the busy spinner uses `delayedIndicator` (300 ms delay, 250 ms minimum).
- Viewer: each image is fetched and decoded by a probe `Image` first; its natural size sets the pane's transform in the same frame the `src` is set, so there is no size jump. Native formats load the raw file; everything else goes through `/api/image/view`.
- Prefetch keeps the decoded neighbours (Preferences, default 2 each side) in a promise cache keyed by URL; entries outside the window are dropped.
- Zoom anchors at the pointer; double click toggles fit and 1:1; zoom of 200 percent and above switches to pixelated rendering.
- The histogram is drawn from the decoded probe at most 256 px on the long side.
- Rotate and flip write the file through the engine (`/api/image/transform`), lossless for JPEG where the engine can; the viewer bumps a per-path stamp so the new pixels load instead of the cached ones.
- Quick look: Space in the browser opens the viewer in quick mode, where Space closes it again.
