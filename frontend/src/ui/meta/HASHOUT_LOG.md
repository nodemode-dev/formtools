# HASHOUT_LOG · ui/meta

## v0.6.0 · 2026-11-03 · All metadata panel (ExifTool)

- `MetaPanel` (`panel.ts`) is one section for the end of the viewer's information panel. It builds its DOM once; everything after that is patched: groups and rows by key with `patchList`, text with `setText`, visibility with `setHidden`. Names and values from files go through `textContent` only.
- Lazy: nothing is requested while the section is closed or no file is shown. Opening it (remembered in `formtools_meta_open`, closed by default) loads the file being shown. `show(entry)` while closed only drops whatever was rendered for another file, so opening never flashes a previous file.
- Requests: every load takes a sequence number and an `AbortController`; the previous one is aborted, and a response whose number is no longer current is dropped, including the follow-up status call. Successful reads are kept in a small cache (8 files, keyed by path, mtime and size), so stepping back and forth in the viewer is instant.
- No flash: the stage reserves 128 px, so opening and loading move nothing. While a new file reads, the old rows stay (copy and row clicks are off, so a stale value is never copied); after 300 ms the rows dim and a "Reading" pill appears; both go the moment the result is rendered. Filter and Copy as JSON are disabled, not hidden, when there is nothing to act on.
- Groups: disclosure rows with a count. The first two are open by default; once the user opens or closes one, the open set (by group name) is stored in `formtools_meta_groups` and applies to every file. While a filter is active every group with a match is shown open and the header toggle is inert, so the stored set is not touched by searching.
- Rows: label left, value right-aligned and wrapping, labels clamped to two lines and values to three. Values over 600 characters are cut for display only; the full text is kept for the title (first 1500 characters), the filter (first 4000) and the copy. Click or Enter copies the full value; Copy as JSON writes `{tool, version, file, groups: {group: {tag: value}}}`, with repeated tag names suffixed ` (2)`, ` (3)`.
- Filter matches label, tag name and value, case-insensitive, debounced 70 ms, by toggling `hidden` on rows rather than rebuilding. Escape clears it, then blurs it; keys typed in it do not leave the field.
- Unavailable: a 415 from `read` shows the engine's sentence (or `status.error`, such as the missing Perl sentence, when present) and the Get ExifTool button. The button runs `POST /api/exif/fetch`, hands the job to `jobs.track` and shows the job's `current` text (or a percentage) in a reserved line; on done it reads again. If `status.fetching` is already true the panel finds the running `exiftool-fetch` job in `/api/jobs` and follows it. The button is disabled, not hidden, while fetching, and when `status.perl` is `false`.
- Sticky: the title row and the filter stick to the top of the scrolling information column (`top` cancels the column's padding), so the filter stays reachable in a long list.
- `icons.ts` adds two original line icons (`metaBraces`, `metaChevron`) merged into `ICONS`; the chevron is rotated by CSS for the open state.
- Smoke test (outside the repo, `scripts-x2/`, real engine on port 8254 with a fetched ExifTool 13.60 and the Vite dev server proxying `/api`): unavailable state, fetch with progress, JPEG read (26 tags, five groups), a slow read of file A overtaken by file B (only B ever rendered), filter, row copy, copy as JSON, open set kept across files, sticky bar, clear. Layout shift between two files with the same groups: zero.
